# libOSIL.so — патч под работу без сервера

Итог: `libOSIL.patched.so` — пропатченная копия `libOSIL.so`, которая проверяет лицензию
локально и **вообще не обращается к серверу**.

```
libOSIL.so          sha256 0392e85f1b57960b6e665cb1d28fb7f08e8920f1789f4bd235d5b0003ed1c81f
libOSIL.patched.so  sha256 4a9c1644fff279d23221276c1373f794f58e6170c91ad50a32276c2738c588c4
размер обоих        5 880 816 байт (структура ELF/сегменты не менялись)
```

## Что именно пропатчено

| # | Адрес | Было → стало | Смысл |
|---|-------|--------------|-------|
| A | `0x56d74c` | `b.lo` → `b` | инициализация больше не прерывается на вердикте встроенной проверки целостности ≥ 2 (патч файла иначе валит старт) |
| B | `0x56f39c` | `b.hi` → `nop` | путь загрузки ядра больше не отсекается при вердикте > 1 |
| C | `0x5730e0` | функция `sub_5730e0` (обращение к серверу лицензий) заменена своей (366 байт) | лицензия выдаётся локально: статус `0`, файл тира пишется, сеть не используется |
| D | `0x56fcf4` | `b 0x56ff34` | `onKeyEntered` принимает **любой** ключ ровно из 12 символов (формат больше не важен, серверной проверки всё равно нет) |

Функция C (см. `tools/patch.py`, содержит ассемблерный листинг):

* аллоцирует и обнуляет структуру ответа → `status = 0`, строки пустые, тир по умолчанию
  (клиент сам подставляет `lunaware`) → дальше пишется `/sdcard/Documents/.tier`;
* если существует `/sdcard/Documents/OSIL/corekey.bin` (32 байта «как есть» **или** 64
  hex-символа), его содержимое подставляется как 32-байтовый ключ ядра, и загрузчик сам
  расшифровывает встроенный блоб (см. ниже).

Хост/IP сервера и константы в файле не тронуты — просто код, который до них доходил, заменён.

## Почему нужен ключ ядра

Внутри файла лежит зашифрованный блоб:

```
смещение 0x1176b, размер 0x551fb8 (5 578 680 байт) — .rodata, энтропия 8.00
шифр     ChaCha20/AEAD ("expand 32-byte k", RFC-8439 тест-вектор в .rodata)
ключ     32 байта, которые сервер присылает в ответ на проверку лицензии
```

Ключ приходит **только от сервера** — вывести его из файла нельзя. Проверено: прогон
`sub_5789d0` на эмуляторе и перебор схем (встроенная 32-байтная константа `f32a93ad…46bc`,
SHA-256 от неё, разные раскладки nonce/счётчика) — расшифровки нет. Поэтому:

* **без ключа** — библиотека работает, лицензия принята, тир записан, но ядро не грузится:
  в logcat `no core to load - inert (key valid, but core unavailable)` (оверлея не будет);
* **с ключом** — положите 32 байта в `/sdcard/Documents/OSIL/corekey.bin`
  (бинарно или как 64 hex-символа) → ядро расшифровывается и грузится **без сервера**,
  дальше работает всё (ядро кладётся в memfd и dlopen-ится, лог `core loaded from memfd jit-cache`).

Ключ можно один раз снять с сетевого обмена оригинального клиента (или взять на сервере) —
после этого библиотека полностью автономна.

## Как пользоваться

1. Взять `libOSIL.patched.so`, положить в APK вместо `lib/arm64-v8a/libOSIL.so`
   (или подменить его в распакованном/установленном приложении).
2. Запустить приложение, ввести **любые 12 символов** как ключ.
3. Если есть ключ ядра — положить его в `/sdcard/Documents/OSIL/corekey.bin` и перезапустить.

## Как проверить, что патч работает (logcat)

```
adb logcat | grep -i osil
```

* `environment ok (v=0)` — гейт целостности пропущен (патчи A/B);
* `tier written: lunaware -> /sdcard/Documents/.tier` — лицензия выдана локально (патч C);
* `network retry …`/`server unreachable`/`acquire status=…` — **не должно появляться вообще**
  (обращения к серверу больше нет);
* `no core to load - inert (key valid, but core unavailable)` — лицензия есть, но нет ключа ядра;
* `core decrypted: …` и `core loaded from memfd jit-cache (…)` — ядро расшифровано и загружено
  (значит, `corekey.bin` на месте и верный).

## Проверка

```
python3 tools/patch.py        # пересобрать libOSIL.patched.so из libOSIL.so (идемпотентно)
python3 tools/test_patch.py   # эмуляция новой функции C: 6 сценариев -> ALL OK
```

`tools/test_patch.py` прогоняет на Unicorn реальный код патча с заглушками `fopen/fread/fclose`:
нет файла → `status=0`, payload пуст; 32 байта → ключ «как есть»; 64 hex → раскодирован;
hex с переводом строки → раскодирован; 20 байт и мусор → ключ не берётся.

## Файлы

| файл | что это |
|------|---------|
| `libOSIL.patched.so` | **готовый пропатченный файл** |
| `libOSIL.so` | оригинал (не изменялся) |
| `tools/patch.py` | патчер + листинг новой функции |
| `tools/test_patch.py` | эмуляционный тест патча |
| `tools/emu.py`, `tools/a64dis.py`, `tools/xref.py` | инструменты анализа (Unicorn-эмулятор AArch64, дизассемблер, поиск xref) |

## Ограничения

* Проверки целостности не удалены из файла, а нейтрализованы в точках принятия решения —
  они продолжают писать диагностику в logcat (`[g] v=…`), но ни на что не влияют.
* Любые проверки **вне** этого `.so` (в Java-коде, в подписи APK, в серверной части) этим
  патчем не затрагиваются.
